How can I ensure that my code, program, or software is functional and secure ?

To ensure that my code, program, or software is functional and secure is to test the quality without any ego or pride and accept the scenario that there might be errors or bugs within the code. Trying to prove or disprove that the code executes the way it is intended to operate is the primary goal. This is one of the reasons having an independent team for testing only is such a popular solution. Another important aspect to take into account is to ideally build the tests into the CI pipelines so they will be able to run as part of the process to prevent a broken build. If the test fails they have to be checked and fixed rather than switching off the testing and run it plainly without any debugging. 

 How do I interpret user needs and incorporate them into a program ?
	
Interpreting the user needs and being able to incorporate them into the program can be a difficult challenge to complete especially when the user may not have a clear picture in mind on what they want or if there is a lack of communication during the process. During the elicitation phase utilizing the 5 why technique is a very useful tool to use to help set a path on what the goal is. Another useful feature that could be utilized is shoulder surfing which is watching a user use other software and ask what they would like and the reasoning behind it on certain things. Lastly, setting up mock-ups on what the potential end result can help prevent any major mistakes within the delivered software. 

 How do I approach designing software ?
	
The way I approach designing software is with a sense of a naive curiosity to help understand the vision of what the user wants and the intended functional requirements. In most cases the user does not know everything up front and using elicitation can help push them to explore their vision further and gather all of the essential steps in requirements collection by playing one of the most important things in communications with the user.
